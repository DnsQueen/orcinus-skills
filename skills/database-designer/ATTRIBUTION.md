- **Script audit (done before bundling):** all three scripts use only the Python standard library (`argparse`, `json`, `re`, `sys`, `collections`, `typing`, `dataclasses`, `hashlib`, `datetime`). No network calls, no database connections, no subprocess, no `eval`/`exec`, no credential handling. Each script writes only to the output file the user names with `-o`, and reads only the input files given. The scripts generate SQL text; they never execute it against a database — applying a migration is the user's step, not the script's.
- **Upstream bugs found and fixed in the bundled copy (2026-11-06, from external reviews):** (1) `migration_generator.py` failed on *any* schema change with `Error: Object of type Column is not JSON serializable`. The changes dict stores raw `Column`/`Table` dataclass instances, and `_generate_migration_id` / `_calculate_changes_hash` call `json.dumps()` on that dict, which cannot serialize dataclasses — so the generator only worked when there were no changes at all. Fixed minimally in the bundled copy with a `_json_default` helper (serializes dataclasses with `asdict()`, raises for anything else), used at exactly the two `json.dumps(changes, ...)` calls. The fix is marked in the file. (2) A unique-only, foreign-key-only or check-only column change produced an empty ALTER (`ALTER TABLE t\n    ;`) — invalid SQL that claimed to do the change and did nothing — because `_columns_different` detected those changes but `_modify_column_step` only converted type, nullable and default to SQL. Fixed: the step now emits the ADD/DROP CONSTRAINT statements for unique, foreign key and check, `_describe_column_changes` now describes check changes, and a detected change with no SQL handler raises instead of generating an empty ALTER. This also closes the eval's recorded FK gap (limitation 2 below): a foreign-key change now produces an ADD CONSTRAINT FOREIGN KEY step. (3) Constraints were added before the old ones were dropped, so a primary-key swap failed. Fixed: constraint removal now runs before constraint addition in `generate_migration`. (4) A table that was both renamed and column-changed lost its column changes, because `_compare_columns` only compares tables with the same name. Fixed: renamed tables now get their columns, constraints and indexes compared (under the old name, since the column and constraint steps run before the rename step), and the rename step records the similarity score and that it is a heuristic to confirm. (5) The zero-downtime path was labelled zero-downtime but had no write-synchronisation, no cutover and no backfill verification, the temp column carried only the data type (not the target's NOT NULL, UNIQUE, DEFAULT, CHECK or REFERENCES), and the DROP COLUMN step inherited the default LOW risk. Fixed: the temp column now carries the target's full definition, DROP_OLD_COLUMN is HIGH risk (RENAME is MEDIUM, COPY is MEDIUM), and the plan summary carries a `zero_downtime_warning` that the output is an expand-contract DRAFT requiring application coordination (dual-write during EXPAND, a backfill check before CONTRACT, a cutover) and must not be run automatically on real data. The other two scripts are untouched. The fixes are covered by `test_migration_generator.py` (11 tests).
- **Tool limitations found by the audit and the eval (not hidden):** (1) the `--format sql` output prints forward steps only — the rollback SQL exists only in the `--format json` output; the skill's rule that every migration needs a reversible counterpart must be satisfied from the JSON output or by hand. (2) ~~The generated SQL does not add a FOREIGN KEY constraint~~ — FIXED (see the fixes above). (3) ~~The `DROP_OLD_COLUMN` step inside the zero-downtime dance is marked LOW risk~~ — FIXED (it is HIGH now). (4) `--validate-only` emits no validation queries for a `DROP COLUMN` step. (5) The rollback for a dropped column re-adds an empty column — it does not restore the data. The skill's own rules (take a logical backup before dropping a column with data; test the down migration in staging) must be applied by the agent, not relied on from the tool.
