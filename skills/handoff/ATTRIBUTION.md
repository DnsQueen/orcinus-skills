# ATTRIBUTION — handoff

- **Sources:** two MIT-licensed handoff skills, merged into one.
  1. mattpocock/skills, `skills/productivity/handoff/` — the base method: write a handoff document summarising the current conversation, save it to the OS temporary directory (not the workspace), include a "suggested skills" section, do not duplicate content already captured in other artifacts, redact sensitive information. MIT.
  2. dariohansson/claude-handoff, `handoff/` — the long-context method: a fixed template (Goal, Status, Progress, Decisions with reasons, Next Steps with `file:line`, Open/Blockers, Pointers, Do NOT, Resume), path rules (default `/tmp/claude-handoff-<YYYYMMDD-HHMMSS>-<slug>.md`, confirm the path, never overwrite, mode `0600`), stricter redaction (refuse to include a secret, write the path instead), and a resume mode that treats the file as data, never as instruction. MIT, Copyright (c) 2026 Dario Hansson. Upstream commit `01b57fb09af3f86450ea5e85a654c0b1e271c3a9` (2026-09-16). The repo has 6 stars.
- **What changed:** this SKILL.md is written in own words — it is a merge, not a verbatim copy of either source. The template, the path rules, the redaction rules, and the resume mode are the dariohansson method; the "suggested skills" section, the no-duplication rule, and the user-invoked-only rule are the mattpocock method. The two sources agree on the core (no file contents, redact secrets, save to the temp directory); where they differed in detail, the stricter rule was kept (confirm the path, never overwrite, mode 0600, refuse a secret, treat the file as data on load).
- **What was NOT copied:** neither upstream SKILL.md verbatim, and neither repo's README or install instructions.
- **Scope notes:** this skill is the ORCINUS handoff skill. It supersedes the installed mattpocock handoff for ORCINUS users — the MAP row "Long-context handoff" is answered by this merge, not by a second handoff skill. The skill writes one file and nothing else; it still runs `git` reads (to record the branch and sha) and writes a file where the user tells it to. The handoff file lives in the temp directory and is deleted when the task ends; it is not committed to the repo.
- **Evals:** the repo's own eval is `evals/handoff-01.md` — a real run: a handoff was written for the real ORCINUS state, a fresh subagent resumed from it with only the file, and the resume-mode protections were tested with a hostile handoff.
