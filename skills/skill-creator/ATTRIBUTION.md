The description is the upstream description with the ORCINUS router-only note appended ('Only invoke via the orcinus router.').
- **Change notice, added 2026-11-06 (round 5):** `SKILL.md` and the three agents in `agents/` (`analyzer.md`, `comparator.md`, `grader.md`) each carry an ORCINUS change notice in the file itself (Apache-2.0 §4(b)) — an HTML comment right after the frontmatter. The notice is invisible in rendering, so the rendered body stays verbatim, and it does not touch the frontmatter. The repo validator checks the notice is present.
- **user-invocable, added 2026-11-06 (round 3):** frontmatter gained `user-invocable: false` — only the router is a user entry point; sub-skills hide from the `/` menu and are invoked by the router. A Claude Code extension field; other hosts ignore it.
- **Agents moved to the plugin root, 2026-11-06 (round 3):** the 3 agents moved from `skills/skill-creator/agents/` to `agents/` at the plugin root — Claude Code discovers agents by folder at the plugin root, not nested under a skill. Each agent file gained minimal frontmatter (`name` == filename, `description` from the file's own opening lines) because Claude Code registers an agent only with frontmatter; upstream ships them as plain instruction files read by the skill. `SKILL.md` now spawns them by name instead of telling the agent to read `agents/<name>.md`. The `eval-viewer/` files stay inside the skill — they are read by the skill, not registered as agents.
- **Frontmatter quoting, 2026-11-07 (round 6, 2-R5):** the three agents' ORCINUS-added `description` values contained an unquoted `: `, which real YAML rejects (PyYAML `ScannerError: mapping values are not allowed here`) — the repo's subset parser used to accept it silently. The descriptions are now double-quoted; the parsed values are unchanged (verified programmatically). The drift manifest hash was updated for all three files.
- **Script audit (done before bundling):** the scripts use only the Python standard library, except `quick_validate.py`, which imports PyYAML (installed in this environment, version 6.0.1). No network calls, no credential handling, no destructive operations. Each script reads the files it is given and writes only to the output path the user names.
- **What does not run in this environment (recorded, not hidden):** `run_eval.py`, `run_loop.py`, and `improve_description.py` invoke the Claude Code CLI (`claude -p`) as a subprocess to run evals and to improve descriptions. That CLI does not exist in this environment, so the scripted eval loop and the description improver do not run here. `quick_validate.py` and `package_skill.py` are pure Python and work here (verified: `quick_validate.py` prints "Skill is valid!" on the skill itself). The skill itself is written for Claude Code (it says "Claude", "claude-with-access-to-the-skill", and describes spawning subagents with and without the skill). Its method transfers to ORCINUS — draft, write test prompts, evaluate, iterate — but the Claude-specific tooling does not; ORCINUS's own eval pattern (real runs with scored evals, as used for every skill in this repo) is the equivalent of its with-skill/baseline loop.
- **Sixth review round (2026-11-07, also from external reviews):** packaging included secret files and followed symlinks: `scripts/package_skill.py` archived `.env` and the contents of a symlink's target (outside the skill) into the `.skill` file, with no file list shown before writing. Fixed: packaging is allowlist-based (only docs, scripts, and data file types) with a printed plan; symlinks are never followed and anything resolving outside the skill is skipped; common secret files (`.env*`, private keys) are rejected unless named with `--allow-secret`; each file is copied from an open descriptor (`O_NOFOLLOW`) and the archive is written to a temp path, checked against the plan (names + SHA256), and renamed atomically; an interactive run asks for confirmation before writing. The `from scripts.quick_validate import validate_skill` import also failed when run as `python3 scripts/package_skill.py` without PYTHONPATH (the documented invocation) — it now falls back to a sibling import. The round-6 fixes are covered by `scripts/test_package_skill.py` (14 tests). The drift manifest hash was updated for this file.
- **Sixth review round (2026-11-07), validator fixes:** `scripts/quick_validate.py` treated empty values as valid (a SKILL.md with `name: ""` and `description: ""` printed "Skill is valid!" and exited 0). Fixed: both fields must be non-empty after strip, and the name must match the skill directory name. `scripts/run_eval.py` converted infrastructure errors into NOT_TRIGGERED (a missing `claude` CLI raised FileNotFoundError, which became False, so a should_trigger: false case passed with exit 0 and no error in the JSON). Fixed: every trial is three-state (TRIGGERED / NOT_TRIGGERED / ERROR); missing CLI, timeout, non-zero exit, and unparseable output are ERRORs, never NOT_TRIGGERED; rates are computed only over valid trials, a query with no valid trial cannot pass, errors are surfaced in the JSON output, and the CLI exits non-zero when any query has none. Both files carry an ORCINUS change notice and are listed in the repo validator's modified-Apache-files list. Covered by `scripts/test_quick_validate.py` (9 tests) and `scripts/test_run_eval.py` (6 tests, including the missing-CLI end-to-end repro). The drift manifest hashes were updated for both files.
- **Round-6 follow-up (2026-11-07), validator allowlist:** `scripts/quick_validate.py` rejected the ORCINUS frontmatter field `user-invocable` as an unexpected key, so 35 of 36 skills failed validation although the repo validator requires `user-invocable: false` on every sub-skill. Fixed: the field is now allowed (no value check here — the repo validator enforces the boolean). Covered by `scripts/test_quick_validate.py` (2 new tests: the field passes, an unknown key is still rejected). The drift manifest hash was updated.
