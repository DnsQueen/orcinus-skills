- **Scope — what this skill is and is not:** this is the *outside* view of a shipped service — uptime probes, health/readiness endpoints, SLO error-budget burn-rate alerts, on-call escalation, and a status page. It complements `monitoring-observability` (OrchestKit, already in this repo), which is the *telemetry* side — Prometheus/Grafana/Langfuse instrumentation and drift detection. The two are not duplicates: `monitoring` detects from the outside, `monitoring-observability` instruments from the inside. A project with no runtime (like the demo library) needs neither, and the router says so.

- **ORCINUS fix to the bundled gate (2026-11-07, round 6, 2-S3 / 3-F2-04 / 3-F2-05):** `scripts/verify.sh` had three defects. (1) A nonexistent target printed SKIP and exited 0 — indistinguishable from a clean config. Fixed: INCOMPLETE, exit 2. (2) Every check grepped one haystack that included full-line comments, so a config whose only mention of burn-rate, runbook, liveness, or opsgenie was in a comment PASSED vacuously — the eval (`evals/monitoring-01.md`) had to strip the comments by hand to make its bad config fail honestly. Fixed: full-line comments (`^[[:space:]]*#`) are stripped before candidacy and before every check. (3) The runbook check was haystack-wide but the skill (and the script's own header) said "a runbook reference on every alert". Fixed in round 6 only in wording: the script's header and `skills/monitoring/SKILL.md` said one reference anywhere in the alert rules passes — it does not prove every alert has one. Round 8 (FND-012) fixed the check itself: `verify.sh` now parses alert blocks (`- name:` / `- alert:`) and requires a runbook reference in EVERY alert; two alerts with one runbook FAIL, naming the alert that has none. When no alert block can be parsed at all, the check falls back to the haystack and says so. The summary now also reports how much was gated (candidate files, alert lines). Residuals, documented in the script: inline trailing comments are not stripped, and the "alert lines" count is an approximation, not a parse. A `\s` in the homepage-probe pattern was also replaced with POSIX `[[:space:]]` — BSD grep -E does not know `\s` (same class as round 6, S10). Tests: `scripts/test_verify_sh.py` (17 tests). An existing path with no monitoring candidates still exits 0 by default — deliberate, documented policy, not a gap; with the round-8 `--require-config` flag it exits 2 INCOMPLETE instead (opt-in strict mode for a project that must have monitoring).
