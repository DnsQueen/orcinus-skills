# EVAL — i18n-01

How to check whether `i18n` works. Follow the skill's own procedure (recon → audit → implement → verify) on a throwaway copy of the demo and its demo page, adding Persian (`fa`) alongside English (`en`). The demo project itself is never touched. No criterion may be skipped.

## Setup (not part of the score)

- The demo has no i18n library and no locales directory. Its user-facing strings are the demo page heading ("Weekly delivery budget") and the summary labels (`total`, `remaining`, `warned`, `percent`) rendered by the page script.
- The error message "budget must be greater than 0" (in `src/budget.ts` and `src/summary.ts`) is developer-facing — nothing in the UI renders it — so it is observed and reported in Case 1 but left out of scope for the implementation, per the skill's own rule (note out-of-scope defects, do not fix them unless the scope widens).
- Each case uses a fresh throwaway copy of the demo page (in `/tmp/orcinus-demo-i18n/`, with `summary.js` copied from the built demo and `locales/en.json` + `locales/fa.json` added). The page loads its locale from `?locale=` (default `en`) and falls back to `en` for a missing key.
- Persian strings used: heading "بودجه هفتگی تحویل", labels مجموع (total), باقی‌مانده (remaining), هشدار (warned), درصد (percent).

## Case 1 — audit finds the hardcoded strings

**Input:** the skill's recon greps run on the throwaway copy (no i18n library present, no locales directory).

**Pass criteria:**

1. The audit names the page heading in `index.html` (file + line) as a hardcoded user-facing string.
2. The audit names the summary labels rendered by the page script as hardcoded user-facing strings.
3. The audit names the error message in `src/budget.ts` and `src/summary.ts` as observed, and records it as out of scope (developer-facing).
4. Verdict is PASS (the audit is complete and honest).

**Fail criteria:**

- A hardcoded user-facing string is not named.
- The error message is silently fixed or silently ignored (it must be named and scoped).

## Case 2 — en and fa both render, no fallback

**Input:** the page wired to the catalog (`locales/en.json`, `locales/fa.json`), rendered in a real browser (Chromium Headless Shell via Playwright 1.64.1).

**Pass criteria:**

1. `?locale=en` renders the heading "Weekly delivery budget" and the English labels.
2. `?locale=fa` renders the heading "بودجه هفتگی تحویل" and the Persian labels (مجموع، باقی‌مانده، هشدار، درصد).
3. Both renders show the same summary values (total 80, remaining 20, warned true, percent 80).
4. The four commands on the throwaway copy exit 0 (build, lint, typecheck, test 7/7 pass).
5. Verdict is PASS.

**Fail criteria:**

- A locale renders with a fallback to the other language (a missing translation showing through).
- A summary value differs between the two locales.
- Any of the four commands fails.

## Case 3 — a missing key falls back to English

**Input:** the `fa` catalog with one key removed (the `warned` label), rendered with `?locale=fa`.

**Pass criteria:**

1. The missing label renders in English ("warned"), not as an empty string and not as a raw key.
2. Every other label still renders in Persian.
3. Verdict is PASS.

**Fail criteria:**

- The missing label renders empty or as a raw key.
- The page fails to render.
